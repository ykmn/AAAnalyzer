# WPF GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a WPF desktop interface that analyzes either the selected Windows output device or an Icecast/HLS URL in real time.

**Architecture:** Keep `SystemAudioAnalyzer.Core` UI- and decoder-independent by accepting a common PCM source contract. `SystemAudioAnalyzer.App` hosts WPF/MVVM, adapts local WASAPI and LibVLC sources to that contract, and renders the immutable `AnalysisFrame` stream on the Dispatcher.

**Tech Stack:** .NET 8, WPF, NAudio, LibVLCSharp.WPF 3.10.1, VideoLAN.LibVLC.Windows 3.0.24, xUnit.

**Spec:** `docs/superpowers/specs/2026-10-06-wpf-gui-design.md`

## Global Constraints

- Target `net8.0-windows` for the WPF executable; keep Core at `net8.0` and free of WPF and LibVLC references.
- Support Windows render-device capture, Icecast URLs and HLS URLs through one PCM-source contract.
- Use a bounded pipeline; stale PCM must be discarded rather than increasing visual latency.
- Waterfall must always render equal-width L and R regions, with content recomputed from normalised coordinates on resize.
- Validate an HTTP/HTTPS URL before Start becomes available in stream mode.
- Preserve `VERSION.txt` format `a.bbb - yyyy.mm.dd`; increment `bbb`, update `CHANGELOG.md`, `TODO.md` and `DONE.md` for each commit.
- `release/rebuild.ps1` must produce a self-contained portable Windows build, including LibVLC native assets.

## Review Focus

- An HLS server with normal multi-second segments cannot meet the Icecast latency target; Task 3 must expose buffering state rather than claiming a low-latency state.
- A stream callback after Stop or source switching must not update a disposed engine; Task 1 tests cancellation and event detachment.
- A malformed or unsupported URL must keep Start disabled and present a local validation error; Task 2 tests this.
- A narrow or wide Waterfall must retain two equal L/R draw regions; Task 4 tests the geometry at multiple sizes.
- A portable publish without LibVLC native files must fail the release check; Task 5 verifies the expected native runtime files in the publish directory.
